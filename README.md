# trit-agent

用三值决策状态机替你在 Minecraft 里操作角色。Windows / 零依赖 Rust / 不需要给游戏装 mod。

配套的起源数据包（召唤师、NPC 能力、传感器）也在这个仓库里。

```
三值决策层   每 5ms 一拍（默认 200Hz，可到 2000Hz）
    ↓ 投票 + 裁决（迟滞 / 弃权）
输入注入层   SendInput 直接打进游戏窗口（键鼠，不是模拟点击）
    ↓
感知回填层   logs/latest.log ← 聊天框 ← 数据包 tellraw
```

## 为什么是三值

状态机不产出「做/不做」两档，而是每个通道产出 `-1 / 0 / +1`：

| 值 | 含义 | 行为 |
|---|---|---|
| `+1` | 明确要 | 执行 |
| `-1` | 明确反对 | 反向执行 |
| `0` | **不知道** | 弃权，交还给人 |

三条硬规则（`src/fsm.rs`）：

1. **没人投有效票 → 松手**。不会因为「默认值」乱动。
2. **未知票权重 > 已知票权重 → 弃权**。这是整个东西的安全底线：
   没感知到敌人时它不会瞎打，血量未知时它不会硬冲。
3. **迟滞**：从 `0` 转到 `+1` 要过 `阈值`，从 `-1` 翻到 `+1` 要过 `阈值 + 迟滞`。
   鼠标抖动、日志延迟导致的来回横跳会被吃掉。

一个反直觉的地方：**阶段转移表不能直接用 K3 的 `and` 写**。
`威胁 AND 血量健康` 在 K3 里会得到 `Neg`（因为 `Neg` 在合取里吸收），
得出「满血 → 不交战」的错结论。所以转移写成 3×3 表，见 `Machine::next_phase`。

## 从 NPC 那里偷来的战术

整合包里的 `hostile_humans`、`enhancedai`、`improvedmobs`、`humancompanions`
这几个 mod 的 NPC 打得很像人，但它们的 Goal 类里没有一处是三值的 ——
全是 `if (distanceToSqr < 49.0)` 这种硬编码阈值。我把这些 Goal 反编译，
把常量池里的数值一个个挖出来（`(N = x²)` 表示原作者写的是 `distanceToSqr`），
然后用三值重写了一遍。见 `src/npc.rs`。

| 移植过来的 | 来源 Goal | 原始数值 | 三值化之后 |
|---|---|---|---|
| 交战距离带 | `hostile_humans/MeleeAttackGoal` + `enhancedai/EARangedBowAttackGoal` | 3 格 / 49.0 = 7² 格 | 远 `+` 追 / **刚好 `0` 站住** / 贴脸 `-` 退半步 |
| 爆炸物规避 | `AvoidCreeperGoal` / `AvoidTNTGoal` | 10.0 / 3.0 格 | `+` 必须躲 / `-` 明确安全 / `0` 无感知 |
| 举盾格挡 | `enhancedai/ShieldingGoal` / `RaiseShieldGoal` | 30 tick = 1.5 秒 | 受伤 + 近身才 `+` |
| 卡住拆墙 | `improvedmobs/BlockBreakGoal` / `DiggingGoal` | 0.5 / 1.1 / 4.0 | 卡住 → 低头 `+` 挥击 `+` |
| 进食安全半径 | `hostile_humans/FoodItemGoal` | 36.0 = 6² 格 | 6 格内有东西就不吃 |
| 巡逻半径 | `humancompanions/PatrolGoal` | radius 12 | 超出半径 → 停，只转头 |

**最关键的是第一行中间那一档。** 原版 Goal 只有「靠近」和「开火」两个分支，
没有「位置刚好、保持住」这个中间态，所以 NPC 会一路挤到你脸上互相卡位。
三值化之后这一段是 `0`，用高权重弃权票表达「位置正好，别推我」——
它天然压掉巡逻和其他前进票，又不会像 `-` 那样把人推回去。

`cargo run --release -- sim` 会把这条曲线跑给你看：

```
tick  phase   move strafe yaw pitch atk jump use  strategy   说明
0     idle     0     0     -    0    0   0    0   -          无敌人
2000  engage   +     -     +    0    +   0    0   -          敌人 ≤32 格 → 追
4000  engage   +     -     +    0    +   0    0   blitz      敌人 ≤10 格 → 继续压上
5000  engage   0     -     +    0    0   0    0   feint      敌人 ≤6 格 → 站住（原版没有这一档）
7000  engage   -     -     +    0    0   +    0   feint      敌人 ≤3 格 → 退半步
8000  engage   -     -     +    0    0   +    0   ambush     敌人在 10 格 + 苦力怕贴脸 → 规避压过追击
12000 engage   +     +     +    +    +   0    0   -          被墙挡住：想追但走不动 → 低头砍墙  [stuck]
```

`move` 列三段 `+` / `0` / `-` 就是这次移植的全部意义。
`strategy` 列是最上层的战法 —— 它不改行为，只调权重，所以你能在同一张表里
同时看到「底层战术」和「上层战法」各自在做什么。

四条战术都能单独关，不想要哪条就关哪条（`trit-agent.toml`）：

```toml
tac_range  = true   # 交战距离带
tac_hazard = true   # 爆炸物规避
tac_guard  = true   # 受伤近身举盾（手上要是盾；拿食物会变成进食）
tac_breach = true   # 卡住低头砍墙
```

游戏内也能切：`!tac off`、`!tac guard`、`!status` 会显示 `tac=+-++` 这样的四位状态。

## 战法：把《孙子兵法》翻译成加权的票

`src/strategy.rs`。五条，一次只生效一条：

| 战法 | 出处 | 判据 | 动作 |
|---|---|---|---|
| **走为上** | 三十六计 | 血 < 35%，或血 < 50% 且被 2 只以上围 | 后退 + 斜向脱离 + 跳 |
| **以逸待劳** | 军争篇 | 血 < 75% 且敌人还在 10 格外 | 高权重弃权压掉前进，站着回血 |
| **兵贵神速** | 九地篇 | 血 > 80% 且只有 1 只且 6~12 格 | 硬推，把「距离带站住」压过去 |
| **围点打援** | 虚实篇 | 2 只以上且 6 格外 | 不冲群，绕到侧面把最前那只放出来单杀 |
| **声东击西** | 三十六计 | 交战中贴身 6 格内 | 持续侧移，方向每 700ms 翻转 |

优先级就是表的顺序，第一个命中的生效：**保命 > 别白挨打 > 能一波就一波 > 别冲人堆 > 贴着别站着**。

三条设计约束（`src/strategy.rs` 文件头有详细理由）：

1. **不新增行为**。行为负责「投什么票」，战法只负责「加权 / 压票」。
   早先试过把战术直接写成行为，结果和移植过来的 Goal 各说各话 —— 一边要冲一边要站，加权后原地抽搐。
2. **只追加票，不改别人的票**。裁决器是加权求和 + 未知吸收，追加一条高权重弃权票就能压住前进，不用去改源票字段。
3. **未知一律不启用**。血量未知就不判「血厚可以冲」，敌人数未知就不判「单敌可以突」。
   战法是有代价的激进决策，拿未知当已知去激进，正是这套系统最不该干的事。

`!strat` 看状态，`!strat off` 全关，`!strat ambush` 单独翻。配置里 `strat_*` 五个开关。

> **踩过的坑**：「兵贵神速」第一版写 `d <= 12`，结果在 4.5 格也判"神速"，
> 把「距离带站住」压掉，角色一路怼到脸上。现在收成 `d > 6.0` ——
> 只在**还在接近的路上**加速，进了交战带就交回距离带。有回归测试锁着。

## 共同意识：一个大脑，多个身体

不是"每只宠物配一个小 AI"——那是多智能体，会互相抢目标、抢路、把怪拉成一团。
这里只有一个意识：**同一份感知、同一套战法**，同时决定玩家自己怎么打、傀儡和狼去打谁。

```
                    ┌─ 玩家角色 ── 键鼠注入（逐帧）
感知 ── 三值状态机 ─┼─ 傀儡/狼 ─── 游戏指令（意图级）
                    └─ 未来通道 ── 实现 CommandSink 即可
```

先装数据包（`squad` 会随 `build_datapacks.py` 一起打进 `dist/`）：

```bash
python scripts/build_datapacks.py --install "E:/MC/MC/profiles/烦人的村民"
```

进游戏 `/reload`，然后收编身边的宠物：

```
/function squad:recruit      # 16 格内最近 3 只狼 + 2 只铁傀儡
/function squad:dismiss      # 解散，回到原版 AI
```

之后 AI 会自动下令（也可以在游戏内手动）：`hold` 待命 / `engage` 交战 / `regroup` 集合 / `recall` 召回。

配置：

```toml
squad = true                 # 打开共同意识（默认关）
squad_control = "chat"       # off = 只算不指挥 / dry = 只记录不真发 / chat = 走命令框真发
squad_engage_dist = 12       # 超过这个距离先集合，别各打各的（会被逐个击破）
squad_recall_hp = 0.45       # 低于这个血量且有威胁 → 召回护主
squad_cmd_gap_ms = 1200      # 两条指令的最小间隔
```

**先设 `dry` 跑一遍再改 `chat`**：`dry` 会把打算发的指令打到控制台但不真的按键盘，
你能确认 AI 的判断对不对，又不用担心它在你死亡界面里乱敲字。

### 为什么只能"意图级"

傀儡和狼没有可注入的输入通道 —— 它们的 AI 是原版写死的 Goal。
唯一能真正改变它们行为的 NBT 字段是 `AngryAt` + `AngerTime`，
而且**只有 `wolf` / `iron_golem` / `polar_bear` 的 Goal 会读它**（见 `src/npc.rs` 的考证）。

所以"操控宠物"在 1.18.2 的物理上限就是：**指定目标、集合、撤回**。
中间怎么走、怎么挥爪子管不了。把这层说明白，比假装能逐帧操控要诚实。

## 采集：真正难的是"什么时候不该砍"

一个只会砍树的 bot 在生存里是负资产 —— 它会在你被三只僵尸追着跑的时候
突然转身去砍旁边那棵树，然后你死了它还站着。

所以这一层的主体不是"怎么砍"，而是**门控**：九条判据全部三值化，
`Neg` 明确不许、`Zero` 不确定（也不许，但不算"危险"）、`Pos` 才动手。
合成规则是「任一 `Neg` 压过全部，任一 `Zero` 降级为不确定」。

| 判据 | 不许砍 | 不确定 → 也不砍 | 默认值 |
|---|---|---|---|
| 威胁 | 有敌人 | 威胁状态未知（刚死过 / 数据过期） | — |
| 血量 | < 65% | 65%~80% 临界带 | `gather_min_hp` |
| 饱食度 | ≤ 7 | 读不到 | `gather_min_food` |
| 爆炸源 | 苦力怕 ≤10 格 | — | — |
| 敌距兜底 | ≤ 16 格 | 威胁判据可能滞后，距离是独立通道 | — |
| 昼夜 | 夜里 | 不知道时间（按夜里处理） | `gather_night` |
| 有没有树 | 视野内没有 / 超过 20 格 | — | `gather_max_walk` |
| 配额 | 这一趟砍够了 | — | `gather_quota` |
| 卡死 | 单棵树砍 25 秒还没断 | — | `gather_max_chop_ms` |

### 三条让它"看起来像人"的机制

**1. 非对称的进入/退出。** 退出是当拍的（慢一点就来不及），
进入要**连续** 2.5 秒明确安全 —— 中间闪一下不确定就重头计时。
这个「攒窗口」是防抽搐的第一道锁。

**2. 被打断要吃惩罚冷却。** 因为威胁退出后锁 8 秒不许开工。
没有这一条，怪物稍微走远一点它就回去砍、砍两下怪又回来 —— 原地抽搐。
真人不会这么干，真人会"这地方不安全了，先走"。

**3. 采集时插播扫视。** 每 1.6 秒停手 350ms，抬头左右看。
砍树时视线是往下压的（`+22°`），正好是视野最差的时候 ——
不主动抬头，就是在最该看周围的时候看着地面。

### 视线闭环

三值只说得清"往哪转"，说不清"转到多少度"。所以数据包把 `Rotation[1]`
也报出来（`p=` 字段），AI 才能把准星精确压到树干上：

```
pitch = 0°   → 投 Pos（往下）   → 推 400ms（22° ÷ 55°/s）
pitch = 44°  → 投 Neg（往上）   → 推 400ms
pitch = 22°  → 一个字都不投     → 停住
```

**不能每拍都投。** 数据包 1 秒才报一次角度，而视线默认转 55°/s ——
一直投 `Pos`，在这 1 秒的"看不见"区间里能转过头 55°，直接从树干冲到脚面，
然后下一拍又往回转，永远振荡。所以实现是「推一下 → 停手等感知 → 再推」。

6100  engage  cd      cd            0     0   -     冒出一只僵尸 → 立刻收手
11000 idle    cd      cd            0     0   -     怪走了，但冷却 8 秒没完 → 不回去砍

`atk` 那列注意区分：**「按住」= 砍方块，「点」= 单次挥击（打怪）**。

### 配置

```toml
gather = true                # 默认 FALSE：采集会主动改变世界，不该默认开
gather_min_hp = 0.65
gather_min_food = 7
gather_night = false         # 夜里不砍
gather_quota = 16            # 一趟砍够多少棵就休息，休息完自动开下一趟
gather_rest_ms = 30000
gather_enter_ms = 2500       # 连续安全多久才允许开工
gather_cooldown_ms = 8000    # 被威胁打断后锁多久
gather_scan_every_ms = 1600  # 插播扫视间隔
gather_scan_ms = 350
gather_reach = 3.2
gather_max_walk = 20.0
gather_max_chop_ms = 25000
```

游戏内：`!gather on|off`、`!gather reset`（清配额和冷却）、`!gather 8`（设配额）、
`!gather night`（夜里也砍）。

### 这一层的能力上限

- **只砍够得着的两三格。** 树干上半截在视野外，砍完下面几格就判"这棵树处理完了"。
  真人砍树也是砍断下面两三格就走 —— 但别指望它把整棵削平。
- **看不见墙。** 探测是"那条射线上 3/6/12 格处是不是原木"，不管中间有没有墙。
  树在墙后也会被判成"有木头"，走过去撞墙。`gather_max_chop_ms` 是兜底：
  25 秒砍不断就放弃并冷却。
- **感知延迟 1 秒。** 数据包最快 20 tick 报一次。所以"冒怪 → 收手"最快也要 1 秒。
  这就是为什么净空半径要给到 16 格 —— 那 1 秒里僵尸能走 4 格多。

## 实测

同一台机器，release 构建，`cargo run --release -- selftest`：

```
目标 200 Hz  · 实际 200.5 Hz · 401 拍 / 2.000s
目标 1000 Hz · 实际 1000.5 Hz · 2001 拍 / 2.000s
```

单拍开销是「构建 WorldView + 6 个行为投票 + 7 通道裁决 + 输入去重」，
不含系统调用。真正拖慢的是 Windows 定时器精度（默认 15.6ms），
所以启动时调了 `timeBeginPeriod(1)`。

## 用法

```bash
cargo build --release

# 先确认能找到窗口和日志
./target/release/trit-agent.exe probe --profile "E:/MC/MC/profiles/烦人的村民"

# 接管
./target/release/trit-agent.exe run --profile "E:/MC/MC/profiles/烦人的村民"
```

首次运行会生成 `trit-agent.toml`。

`probe` 找不到窗口时会把所有可见窗口连**类名**一起列出来。类名是关键信息：
Minecraft 走 LWJGL3，窗口类名是 `GLFW30`，而启动器的类名是 `Tauri Window` /
`Chrome_WidgetWin_1` 之类。只按标题「包含 minecraft」找会抓错 ——
HMCL 的窗口标题 `Hello Minecraft! Launcher` 同样包含 minecraft，
抓错的后果是给启动器改标题、对着启动器发键，游戏一动不动。
所以 `find_window` 的顺序是：标题命中且类名 `GLFW*` → 标题以关键字开头 → 标题包含。

### 热键

| 键 | 作用 |
|---|---|
| **`F8`** | **一键交还控制权**。按一下关：立刻松开所有键 → 切回第一视角 → 标题变 `[AI 待机]`。再按一下重新接管 |
| `F9` | 急停。关掉 AI 但**不切视角**（想保持第三视角看场面时用） |
| `F10` | 切视角：第一 → 第三背视 → 第三前视 → 循环 |
| `F6` | 单独开关「攻击」这一项次操作 |
| `F7` | 单独开关「移动」这一项次操作 |

为什么是 `F8`：原版 1.18 的默认绑定里 `F5` 是视角、`F3` 是调试、`F1` 隐藏 HUD、
`F2` 截图、`F11` 全屏，`F6`/`F7` 常被 mod 占；只有 `F8` 是空的，而且和 `F5` 相邻，
左手一伸就能按到。不想用 `F8` 就改 `kill_switch_vk`（虚拟键码）。

热键是全局的 —— 即使焦点在浏览器上也能按 `F8` 把 AI 停掉。

### 关掉它的时候到底发生了什么

按 `F8` 是一串动作，不是一个布尔值：

1. `release_all()` —— 立刻发 KEYUP，不等下一拍。否则当前这一帧你还按着 `W`，
   下一帧就是人和 AI 抢键盘。
2. 状态机进 `Off`，所有通道弃权（`Zero`）。
3. 若 `restore_first_person = true`（默认）：注入 F5 切回第一视角。
4. 窗口标题变 `[AI 待机]`。

第 3 步和第 4 步是给"人"的信号。没有它们，你按了 `F8` 之后只能靠"角色是不是还在动"
来猜 AI 死没死。

### 游戏内聊天指令

AI 开着的时候直接在聊天框里打字。

> ⚠️ 但**推荐直接用 `F8` 而不是打 `!` 指令**：AI 在持续注入 `W`/`A`/`S`/`D`，
> 你一打开聊天框，这些键就会变成聊天内容（`!ai off` 会变成 `w!ai off`）。
> 要打字就先用 `F8` 让开键盘。

```
!ai off              交出控制权
!status              看当前阶段/血量/战法/共同意识/采集
!mode patrol         切换 hold / patrol / follow
!attack off          只关攻击，其他照常
!move off     !look off     !jump off     !use off
!tac off             关掉四条移植战术；!tac guard 只翻格挡
!strat               看战法；!strat off 全关；!strat ambush 单独翻
!squad               看共同意识；!squad on|off；!squad recall 手动下令
!gather              看采集状态；!gather on|off|reset|night；!gather 8 设配额
!threat              手动标记「有威胁」
!calm                手动标记「安全」
!panic               急停
```

每一项「次操作」都能单独摘掉，摘掉后那一路通道永久 `Zero`，AI 不再碰它。

### 第三视角

接管时会自动切到第三视角（默认背视）。

原版 F5 是个**三态环**：第一 → 第三背视 → 第三前视 → 第一。问题是我们读不到当前在哪一档，
所以第一次切换**不猜**：按满一圈（3 次必回第一视角）再走到目标。

多按两下，换来的是「不管你开局停在哪一档，落点都确定」。直接按 1 次的话，
如果你本来就在第三背视，会被切成第三前视（画面在人物正面，操作极难受）。

`perspective_presses` 是目标档位：`0` 第一视角 / `1` 第三背视 / `2` 第三前视。
`restore_first_person = true`（默认）让交还时切回第一视角 —— 第三视角下人手操作很难受。

接管和交还这两个动作走的是**强制路径**（永远按满一圈），所以你中途自己按游戏 F5 看风景、
把档位搞得跟账面不一样，也不影响：按 `F8` 关掉时依然准确落回第一视角。
`F10` 走的是账本差值路径（快），适合 AI 开着时你想临时换个角度看。

### 窗口失焦时自动停手

`pause_when_unfocused = true`（默认）。`SendInput` 是**系统级**注入，
游戏失焦后注入照样生效 —— 你 Alt+Tab 去看个网页，AI 会继续往浏览器里敲 `w`、
点左键。所以只要 `GetForegroundWindow() != 游戏句柄`，一个键都不发，决策照常跑。

这一条也保护了 F5：切视角前单独查一次前台，否则浏览器里 F5 = 刷新，网页就没了。

跑完会打印 `后台暂停 N 次`，看到这个数说明中途切出去过。

## 数据包

```
datapacks/
  summoner_origin/   召唤师起源：3 只战狼 + 铁卫，召唤物会主动打村民和整合包敌对 NPC
  npc_origins/       给 NPC 挂「起源式」效果（打 tag 生效，默认无副作用）
  trit_bridge/       传感器：把血量/坐标/敌人/原木/俯仰角写进聊天，供状态机读
  squad/             共同意识的执行端：receive 意图 → 改傀儡/狼的 AngryAt
  summoner_lang/     召唤师起源的中文名称（资源包）
```

安装：

```bash
python scripts/build_datapacks.py --install "E:/MC/MC/profiles/烦人的村民"
```

进游戏 `/reload`，然后：

```
/function trit_bridge:on      # 开传感器（默认关，因为会占聊天框）
/function trit_bridge:off
```

传感器输出长这样，每秒一行：

```
<TRIT hp=185 food=17 x=123 y=-601 z=88 h=3 d=6 c=0 w=6 wd=-1 t=15200 p=22>
```

| 字段 | 含义 |
|---|---|
| `h` | 32 格内敌对实体数（上限 32） |
| `d` | 最近敌人的距离档：`3 / 6 / 10 / 16 / 32`，0 = 视野内没有 |
| `c` | 最近爆炸源（苦力怕/TNT/末影水晶/火球）的距离档，同上 |
| `w` | 最近原木的距离档：`3 / 6 / 12`，0 = 8 方向都没命中 |
| `wd` | 原木方位：`0` 正前，负左正右，单位 45°（`-3..=4`，4 = 背后） |
| `t` | 游戏内时间 `0..23999`，用于判昼夜 |
| `p` | 视线俯仰角（度），`-` 往上、`+` 往下 |

距离档是「≤N 格」，用几次半径判定从远到近覆盖取最近那档，比遍历实体算精确
距离便宜得多。Rust 侧按档内代表值使用，且**故意取偏小一侧**——
「以为更近」只会多退半步，「以为更远」才会莽上去。

原木探测打的是**水平射线**：`execute at @s rotated ~45 0 if block ^ ^ ^6 #minecraft:logs`。
`rotated ~D 0` 保留玩家 yaw、把 pitch 压平 —— 低头砍树时射线也不会打到脚面上。
近距离档（3 格）额外扫 `-45° / 0° / +30°` 三个俯仰，覆盖树干的下 / 中 / 上；
因为眼高那格一被砍掉，纯水平射线就再也命中不了树干，AI 会以为树没了，
其实还剩五六格。

`d` / `c` / `w` / `wd` / `t` / `p` 都是后加的字段，旧版数据包不带也能跑
（按 0 处理，等价于「没感知」）。反过来也一样：Rust 侧不认识新字段就忽略。
两边可以独立升级。

## 诚实的边界

**它能做的**：稳定的战斗节奏（挥击 / 跳劈 / 换边）、卡血撤退、低血站桩回血、
死亡后点重生、巡逻扫视、随时接管与交还。

**它做不到的**：

- **没有视觉，也不知道敌人方位**。数据包只给「最近敌人多远」，不给方向。
  所以视角不会朝敌人转（`Yaw` 只在待命时才扫视），也不会主动走位绕后。
- 不开数据包时它只有「日志里写了什么」，也就是死亡消息和你打的字。
  这时候 `assume_threat = false`（默认）会让它站着不动 —— 这是刻意的，
  猜错方向的代价比不动大。
- **反应延迟 ≥ 1 个传感器周期**（默认 1 秒）。这是「日志 → 状态机」这条链的
  物理下限，高频节拍抹不掉它。想要更低只能写 mod 直接读内存。
- **不认路、不会寻路**。没有 `baritone` 那种路径规划。采集是「我看见了、
  直线走过去」，中间隔一堵墙就只会砍墙（`tac_breach`）。
- **采集只覆盖原木**。换成挖矿要改数据包里的方块判据（`WOOD_BLOCK`），
  而且得挑镐 —— 外部注入没法可靠换槽位。
- **鼠标灵敏度要手调**。MC 的「每像素转角」跟灵敏度设置强相关，
  默认 `look_gain = 1.35` 是按灵敏度 0.5 估的。转太快就调小，转太慢就调大。
- **手眼要分开看**：AI 会抢你的鼠标和键盘。按 `F8` 关掉才是安全的对话姿势。

**没做的验证**：本机没在真游戏里跑过端到端（这机器同时开游戏和编译会打架）。
已验证的是：132 个测试（K3 真值表、平衡三进制往返、迟滞不抖、弃权优先、
日志解析、端到端日志→决策、采集门控、视线闭环限速）、release 构建 0 警告、
高频实测数据、数据包 JSON 与 `function` 引用校验。
第一次实机如果有问题，看 `trit-agent-run.log`（每 100ms 一行决策编码），
或者 `docs/BOUNDARIES.md` 里记的那几个已经踩过的坑。

**采集这一层额外没验证的**：原木射线的实际命中率（多高、多远、树干细的时候
漏不漏）、`rotated ~D 0` 在 1.18.2 的取值语义、`#minecraft:logs` 覆盖了哪些方块。
这三个都只能进游戏才能确认。手上没把握就先用 `gather_quota = 1` 试一趟。

## 和 `bfxh/trit` 的关系

同一套三值语义，不同的落点。`trit` 把三值用在逻辑求值、打包、GPU 内核上；
这里把三值用在**实时决策**上：`Unknown` 不参与猜测，只用来表达「弃权」。
