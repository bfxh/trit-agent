# 边界与已知问题

这份文档记录「实测过什么 / 没实测什么 / 哪些判断是刻意的」。写清楚边界比多一个功能重要。

## 1. 感知的真实来源

| 来源 | 内容 | 延迟 |
|---|---|---|
| `trit_bridge` 数据包 `tellraw` → 聊天 → `latest.log` | 血量、食物、坐标、16 格内敌人数 | ~1s（20 tick 一次 + 日志刷盘） |
| 死亡消息 | 「was slain by」等 30 种死法 | ~0.2s |
| 玩家聊天 | `!ai off` 这类指令 | ~0.1s |
| `/data get` 回显 | 一次性血量查询 | 需在游戏里手动敲 |

**没有**：可视画面、实体朝向、方块碰撞、背包内容、敌对实体的距离与方位。
所以「敌人从左边来」这种判断做不到，只有「附近有几个」。

## 2. 为什么不用 OC（读屏）

试过的方向：截屏 + 找血条红像素。放弃原因：
- 这个整合包 HUD 被多个 mod 改过（血量可能有额外条、护甲条、饥饿条位置漂移）
- 20 次/秒的截屏 + 分析在本机是 5~15% CPU，且分辨率一变就失效
- 失败方式是**静默的**：认不出血条时会当成满血，比没有感知更危险

数据包方案失败时会立刻可见（聊天没出 `<TRIT` 行），排查成本低一个量级。

## 3. 高频节拍的实际意义

200Hz 不代表 200Hz 的反应速度。它解决的是**输出抖动**：

- 游戏输入是 20 TPS 采样。200Hz 内部节拍让「按 50ms」这类脉冲总能被采到，
  不会因为对齐问题漏帧。
- 视角是连续量，高频累加让转角更平滑，避免 20Hz 下的阶梯感。

反应速度由感知决定，不是节拍。

## 4. 会打架的地方

- `F5` 被注入用来切第三视角。如果你正好在按 F5，会多切一次。
  想自己换角度就按 `F10`（走 agent 的账面），别按游戏内 F5，
  否则账面和画面对不上 —— 不过接管/交还走的是「按满一圈」的强制路径，
  所以漂了也不影响 `F8` 关掉时准确回到第一视角。
- 注入 F5 前会单独查一次前台。不在前台就一次都不按 —— 浏览器里 F5 是刷新。
- AI 开着的时候不要打字 —— 你打的字会进聊天框，同时 AI 在按 WASD，
  结果是角色乱走 + 聊天框里一串乱码。先 `F8`。
- 窗口失焦时 AI 自动停手（`pause_when_unfocused`），但**决策还在跑**。
  回到游戏的那一拍不会重放暂停期间错过的动作，只是从当前状态继续。
- `!` 开头的聊天消息会被当成指令。正常聊天别用 `!` 开头。
- 疾跑默认按住 Shift，会消耗饥饿值。

## 5. 踩过的坑（已修，留档）

1. **5ms 点击会被整帧漏掉**。第一版把「攻击」当成 1 拍的高电平，
   5ms 按下立刻松开。游戏输入是按帧（~16ms）采样的，这个脉冲大概率
   完全落在两帧之间 —— 表现是「AI 站着不打人」。
   现在所有点击/跳跃都有最小按住时长（70ms / 90ms），并有回归测试锁住。
2. **K3 的 `and` 不能直接写阶段转移**。`威胁 AND 血量健康` 在 Kleene 逻辑里
   会得 `Neg`（Neg 在合取中吸收），推出「满血 → 不交战」。改成了 3×3 转移表。
3. **行为落后一拍**。行为模块读的是上一拍的阶段，导致刚进入交战的那一拍
   不会挥击，日志看起来像「进战了但没动」。改成先 `peek` 出本拍阶段再投票，
   同一套纯函数算两遍，结果一致。
4. **死亡后误判持续交战**。原先把死亡消息当成「战斗接触 60 秒」，导致重生后
   立刻又进入交战。现在死亡只做三件事：标记死亡、威胁降级为未知、清空接触。
5. **重生点击失控**。死亡界面没弹出来时（比如 Esc 菜单挡着）会无限点屏幕中心。
   现在连点 12 次就主动 `arm(false)` 交还控制权。
6. **迟滞把低权重票锁死**。`ChannelCell::decide` 在上一拍已是已知值时，把门槛
   抬到 `阈值 + 迟滞`。`Strafe` 原来是 `(1, 2)`，而 `Combat` 每拍只投权重 2 ——
   2 永远小于 3，于是**一旦换过边就再也换不回来**，表现是「AI 只往一个方向
   横移」。`Yaw` 是 `(2, 2)`、票权 1，更严重：视角永远不转。
   规则改成：**每拍都有人投票的通道，迟滞不能大于票权重**（`Strafe` → `(1,1)`，
   `Yaw` → `(2,1)` 且扫视票提到 3）。教训是「迟滞」这种防抖手段会顺手把
   正常信号也滤掉，得按通道的票权分布来定，不能一刀切。
7. **同一件事两个来源互相抵消**。`Patrol` 和 `IdleScan` 各自维护一套扫视计时器
   和方向，在 Idle 阶段同时投票、方向相反，加权和正好为 0 ——
   表现同样是「视角永远不动」，但根因和上一条完全不同。
   修法是删掉 `Patrol` 里的扫视，扫视只留 `IdleScan` 一个来源。
8. **用首尾位移判卡住会误判走位**。第一版卡住检测拿「窗口首尾的直线距离」，
   角色原地左右横移时净位移接近 0，被判定撞墙，然后低头砍地。
   改成两条：① 只在前**后**键按下时判定（「卡住」的语义就是「想前进但前进不了」，
   横移不算）；② 注释里写明数据包 1 秒一报，本质是 1 秒净位移。
9. **`0` 当哨兵值和 `now_ms == 0` 撞车**。卡住检测用 `pos_win_start == 0` 判断
   首帧，但第一次采样可能真发生在 `now_ms == 0`，于是第二个窗口被整个吞掉，
   表现是「卡墙了但一秒后才反应过来」。改用 `pos_last.is_none()`。
10. **满血按右键会误吃**。`Guard` 最初只要贴脸就按右键。MC 里右键是「举盾」
    还是「进食」取决于手上拿的是什么 —— 拿食物时按下就是 1.6 秒进食动画，
    期间打不出伤害，比不挡更糟。现在只在**掉过血**（<60%）且近身时才按。
11. **墙体掩码的方位是反的，而配套测试也照错的写**。位序是「yaw 偏移 +i×45°」，
    MC 里 yaw 增加是**往右转**（0=南、90=西，从南到西是顺时针），所以正右方
    是位 1。第一版写成「往左转」，`dir=+1` 落到 7、`-1` 落到 1 —— 整体镜像。
    更麻烦的是当时那条单测也是照错的假设写的，所以全绿。
    这类「方向反了」的 bug 不会崩，只会让 AI 往墙的反方向绕，
    看起来像「故意的」。**测试的期望值必须从独立事实推出来，不能从实现推。**
12. **感知补丁不能把没报的字段写成默认值**。快通道只报俯仰角和碰撞，
    如果每帧都把整份状态重建一遍，「有几个怪」每 100ms 被清成 0，
    AI 会以为世界永远安全。改成补丁：`SensorPatch` 里全是 `Option`，
    缺的字段保持原值。同理，`wall: None`（不知道）**不能**当 `wall: 0`（没墙）。
13. **"卡住"在挖矿时一定成立，于是 `Breach` 抢走了左键**。挖矿本来就不移动，
    `stuck` 判据必然为真，`Breach`（撞墙就低头挖）立刻接管 Pitch 和 Attack，
    把采集的瞄准闭环和挖掘进度全打乱 —— 表现是「对着矿旁边那面墙猛挖」。
    修法：`c.gather.active()` 时 `Breach` 和 `IdleScan` 都退场。
    教训是**两个行为对同一通道都有意见时，得先想清楚谁在什么阶段该闭嘴**，
    光靠权重压是压不住的（权重只决定方向，不决定该不该说话）。
14. **扫视抬视线 = 每 1.6 秒把瞄准清零一次**。原设计里插播扫视会把视线抬回
    `-8°` 再压回来，理由是"抬头看看远处有没有怪"。但威胁不是靠看的 ——
    数据包一直在报 16 格内的敌人数。抬视线的唯一实际效果是把正在挖的方块
    丢掉再花大半秒压回去，等于一半时间在跟自己的视线较劲。改成只水平扫。
15. **一格土坎和两格墙长得一样**。"1 格处是固体"这个判断对两者没有区别，
    但前者该跳、后者该绕。缺了区分，AI 会把每个土坎都当死路 ——
    表现是「明明能走的地方它站住不动」，且只在有地形起伏处发作。
    加了一条 `unless block ~ ~1 ~` 判上方是否也是固体，单独报一位。
16. **延迟不能写死**。「推一下 → 停手等感知 → 再推」里那个"等"，
    写 900ms 则装了快通道也白装，写 100ms 则只有慢通道时一路转过头。
    改成运行时测帧间隔（EWMA，<30ms 视为同拍重合丢弃），等 `间隔 × 1.4 + 30`。
    另外慢帧和快帧会撞在同一 tick（20 能被 2 整除），那一帧间隔是 0，
    不滤掉会把估计一路拉到 0，于是等待变 0、AI 开始疯狂转头。

## 6. 从 mob mod 移植时放弃的东西

反编译了 `hostile_humans` / `enhancedai` / `improvedmobs` / `humancompanions`
的 Goal，有几条**做不到**，如实记下：

| 它们有 | 为什么做不了 |
|---|---|
| `MoveBackToPatrolGoal`：离岗后回原位 | 回位需要知道朝向（yaw），外部驱动读不到。降级成「超出半径就站住不再走」，不会回家。 |
| `WitchBuffAllyGoal`：给友军上 buff | 需要知道哪个实体是友军，且要能选中它 —— 只能打自己，没意义。 |
| `GetOverHereGoal` / `PearlUseGoal`：传送追击 | 要切物品栏到珍珠并瞄准，外部驱动没有物品栏状态。 |
| `BlockBreakGoal` 的完整版：算路径挖穿墙 | 只有「低头挥击」，挖哪里取决于当前视线，不保证挖对。 |
| `EAAvoidEntityGoal`：避开任意指定实体 | 数据包只能列固定 tag，做不到按需指定。 |

结论：能移植的是**判据**（距离、冷却、血线、危险源），移植不了的是**寻路和
物品栏操作**。前者是三值化的强项，后者需要 mod 层面的接口。

## 7. 没验证的部分（如实列出）

1. **真机端到端**：没在运行中的游戏里跑过。已验证的是仿真链路（日志文本 → 决策 → 输入调用）。
2. **`SendInput` 在 LWJGL 窗口的表现**：理论上可行（内核级注入，绕过消息队列），
   但本机窗口没开游戏，没实际按过。
3. **数据包 `execute store result score ... run data get`**：语法按 1.18.2 写的，
   JSON 已校验，但没在游戏里 `/reload` 验证过实际输出。
4. **`trit_bridge` 的敌对实体清单**：106 条，mod 实体用 `required: false`，
   对应 mod 不在也不会报错。
5. **快通道的聊天刷屏观感**：每 2 tick 一条，动手期间等于每秒 10 行。
   命令数不是问题（合计 23 条/tick，原版自己每 tick 跑上千条），
   问题是玩家看不看得下去。所以默认按需开、收手 2.5 秒后关；
   嫌吵可以 `gather_fast_bridge = false`，AI 会自动回落到 1 秒档。
6. **`#trit_bridge:solid` 的覆盖范围**：16 个原版 tag + 96 个方块拼出来的，
   原版**没有** `#minecraft:solid` 这种 tag。哪些方块漏了只能进游戏才知道，
   漏掉的后果是「AI 以为能过去然后撞上」，由 `stuck` 检测兜底。

## 8. 出问题先看哪里

```bash
# 窗口找没找到
trit-agent.exe probe

# 决策回放：每 100ms 一行，格式 "毫秒 阶段|七通道编码 血量"
cat trit-agent-run.log | head -50

# 游戏日志里有没有传感器输出
grep -a "<TRIT" "E:/MC/MC/profiles/烦人的村民/logs/latest.log" | tail -5
```

阶段编码对照：`off / idle / engage / retreat / recover`，
通道顺序：`move strafe yaw pitch attack jump use`，字符 `+ 0 -`。
