
## trit-agent：双通道感知 + 挖矿 + 墙体（9279f50，已推 GitHub）

**核心结论**：外部程序只能读日志 → 所有感知挤在一条 1 秒通道上是错误的根源。
拆成快慢两条：快 2 tick（瞄准角 / 墙体掩码 / 准星与脚下方块 / 台阶位），
慢 20 tick（敌人 / 资源射线 / 时间）。快通道默认关，动手时才开、收手 2.5s 后关。

**关键技术点**
- 8 方向墙体用 `scoreboard players add 1<<i` 累成 8 位掩码，一个 score 传 8 个 bool。
- 方块归成 7 类（空/木/矿/固/水/岩浆/危险），靠"高优先级后 set"实现分类，
  一个位置 6 条 `if block`。原版没有 `#minecraft:solid`，自建 16 tag + 96 方块。
- 台阶 vs 墙靠 `unless block ~ ~1 ~ #solid` 单独报一位，否则每个土坎都被当死路。
- 延迟不写死：实测帧间隔 EWMA（<30ms 丢弃），等 `间隔×1.4+30`；
  **非对称滤波**——变慢立刻认，否则快通道一关十几秒内每推都转过头。
- Rust 侧 `SensorPatch`（全 Option）合并两通道，缺字段保持原值；
  `None` 必须区别于默认值（不知道有没有墙 ≠ 没有墙）。
- 快帧要用独立时间戳 `fast_at`，不能用 `sensor_at`（慢帧会刷新它 → 数据假的"新鲜"）。

**踩的坑（已验证修复）**
1. 墙体掩码方位镜像：MC 里 yaw 增加是**往右转**（0=南 90=西），正右=位1。
   当时配套单测也照错假设写 → 全绿。教训：测试期望必须从独立事实推，不能从实现推。
2. 挖矿时 `Breach` 抢左键：挖矿不移动 → `stuck` 恒真 → 对着矿旁那面墙猛挖。
   修法：`c.gather.active()` 时 Breach 与 IdleScan 都退场。
3. 扫视抬视线 = 每 1.6s 把瞄准清零。威胁靠数据包不靠看，改成只水平扫。

**性能**：`classify` 早退（不含 `[CHAT]` 直接返回，不再对每行跑 26 次死亡标记搜索）；
`LogTail` 改游标消费（去掉逐行 drain 的 O(n²)）；缓冲复用。

**验证**：176 测试全绿、release 0 警告、sim --gather / --mine / selftest 实跑、
数据包已装进三个存档（9.1KB，20 条目含 sense_fast/fast_on/blocks tags）。
**未实机验证**：注入路径、射线命中率、`rotated ~D 0` 语义、标签覆盖范围、刷屏观感。
